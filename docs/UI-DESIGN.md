# 界面规范（Windows 端）

> 2026-11-20。四端共用同一套视觉语言，取值以 Windows 的
> `apps/windows/DvPlayer/Themes/AppTheme.xaml` 为准。

## 1. 色板

深色影院风：深灰打底、中性层次、琥珀色强调。**不用纯黑**——纯黑在
大屏上会把卡片边界吃掉，整屏也发闷。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 背景 | `#141419` | 页面底色 |
| 侧栏 | `#17171D` | 侧栏、窗口顶部 |
| 卡片 | `#1F1F27` | 面板、媒体卡片、输入框 |
| 卡片悬停 | `#2B2B35` | 悬停态、下拉弹层 |
| 分隔线 | `#3B3B49` | 描边、卡片边界 |
| 正文 | `#F5F5F8` | 标题、主要内容 |
| 次级 | `#BDBDCB` | 说明文字、导航默认态 |
| 弱化 | `#9696A4` | 时间戳、占位符、极次要信息 |
| 强调 | `#FFB020` | 主按钮、选中态、进度 |
| 危险 | `#FF6B6B` | 错误、删除 |
| 成功 | `#4ADE80` | 连接成功 |

### 对比度（WCAG 2.1）

| 前景 / 背景 | 背景 `#141419` | 卡片 `#1F1F27` | 悬停 `#2B2B35` |
| --- | --- | --- | --- |
| 正文 `#F5F5F8` | 16.9:1 | 15.0:1 | 12.9:1 |
| 次级 `#BDBDCB` | 9.9:1 | 8.8:1 | 7.5:1 |
| 弱化 `#9696A4` | 6.3:1 | 5.6:1 | 4.8:1 |

三条都过 AA（4.5:1），弱化色在小字号下也够用。改色板时按这张表复核，
不要往 4.5 以下走。

## 2. 字号

| 角色 | 字号 | 字重 |
| --- | --- | --- |
| 页面标题 | 27 | SemiBold |
| 区块标题 | 17 | SemiBold |
| 卡片标题 | 14 | SemiBold |
| 正文 / 按钮 / 输入框 | 13.5 | Regular |
| 说明文字 | 12.5 | Regular |
| 角标、时间戳 | 11.5 | Regular |
| 极小图标（角标内） | 10.5 | Regular |

规则：

- **正文不小于 12.5**，11.5 只用于角标与时间戳这类辅助信息；
- 层级靠字号 + 字重 + 颜色三者区分，不要只靠颜色（弱化色不是灰到看不清）；
- 标题用 `DisplayFont`（Segoe UI Variable Display），正文用 `AppFont`；
- 首屏里的大标题（Hero 片名）可以到 38–56，属于展示性文字，不受上表限制。

## 3. 控件约定

- **窗口 chrome**：不要标题栏。`FluentWindow` 打开 `ExtendsContentIntoTitleBar`，
  内容从窗口最顶上开始，最小化 / 最大化 / 关闭自己画在
  右上角（`CaptionButton` / `CloseCaptionButton`，46×32，悬停 `#2B2B35`、
  关闭悬停 `#C42B1C`）。顶部 36px 当标题栏用：拖动移窗、双击最大化。
  页面工具条因此从 40px 起，右上角的控件（首页刷新、记录页分段、搜索框、
  服务器页按钮）要给三个按钮让出位置，别让它们压在按钮底下；
- **侧栏服务器列表**：每行前面一个 6px 状态点——连上绿（`SuccessBrush`）、
  没连上红（`DangerBrush`），和 macOS 一致；这个点取代原来行首的服务器图标，
  状态一眼能看出来，不用再读文字；
- **侧栏左下角**：只显示「版本 x.y.z」（应用版本，悬停提示里是共享核心版本），
  不放任何按钮，也不再写「已连接 / 未连接」那行；启动后查到新版本时下面多一行
  可点的「可更新 vX」，点开「设置 → 关于」。连接状态看上面服务器列表的状态点，
  出错的详细原因在「服务器」页；加本地文件夹也走「服务器」页（见
  `LOCAL-SOURCE.md`）；
- **圆角**：卡片 12、按钮 / 输入框 / 下拉框 9、小角标 5–6；
- **焦点框**：主题层把所有 `FocusVisualStyle` 设为 `{x:Null}`。按 Alt
  不会再多出一圈虚线框，键盘操作靠选中背景辨认；
- **搜索框**：`SearchBoxBorder` + `SearchBoxInput` + `SearchBoxPlaceholder`，
  整块挂 `controls:SearchBoxFocus.Enabled="True"`（点图标 / 内边距也能开始输入）；
  `SearchBoxInput` 的模板里 **不要再给 `PART_ContentHost` 加
  `Margin="{TemplateBinding Padding}"`**——TextBox 引擎已经套过一次 `Padding`，
  双重内边距会把文本挤出可视区，只剩一根光标（看起来像字体颜色不对）；
- **下拉框**：不要用系统模板（深色主题下弹层是白底），统一用
  `{StaticResource Select}`，里面已经把弹层、选中项、箭头都重画了；
- **顶栏**：始终浮在内容上，只用顶部渐变压暗，**不要做实底**——实底会在海报上
  切出一条黑带。滚动后把第二层渐变淡入即可，别换成纯色块；
- **半透明浮层**（顶栏分段、海报角标）：黑白叠加透明度，不引入新色相；
- **滚动条**：常规页面纵向滚动条隐藏；**网格页**（库内容 / 搜索结果）右侧显示
  一条 10px 宽的深色滚动条（滑块白 24%，悬停 35%，拖动 46%），让用户知道还能
  往下滚；横向海报行不用滚动条，自己带左右箭头；
- **确认框 / 提示框**：不要用系统的 `MessageBox`（浅色弹窗，和深色界面完全不搭），
  统一用 `Dialogs/ConfirmDialog`：`#1F1F27` 圆角卡片 + 自带阴影，危险操作
  （删除源等）用红色 `DangerButton`，正文 `Muted`；回车 / `Esc` 都走「取消」，
  删除不靠回车误触。`ConfirmDialog.Alert` 是只有一个「好」的提示框；
- **右键菜单**：深色圆角浮层（`DarkContextMenu`），项高 34、图标 24 宽，
  分组之间用 1px `Line` 分隔线；不用系统浅色菜单。图标统一用 `IconFont`，
  颜色 `Muted`，文字 `Text`；
- **横向行**：行内不放常驻箭头，鼠标移到这一行才在左右两侧浮出半透明圆钮
  （`RowArrowButton`）；滚轮始终交给页面纵向滚动，横向只能拖或点箭头；
  点箭头走 `SmoothScroll.ScrollBy`（260ms 缓出），所有页面共用这一个入口，
  不要各自直接调 `ScrollToHorizontalOffset`；
- **横向行容器**：一律用 `Controls/HorizontalRow`（`ScrollViewer` 派生），别手写
  `<ScrollViewer HorizontalScrollBarVisibility="Hidden" VerticalScrollBarVisibility="Disabled">`。
  它在 Preview 阶段把滚轮转给最近的纵向 `ScrollViewer` 并标记已处理——自己写
  经常漏掉、或者从错的节点往上找，结果鼠标停在封面上整页就滚不动了；
- **大图收尾**：横幅 / 详情页大图的渐变要**淡到页面底色**（`BgColor` `#141419`），
  不要用纯黑或别的深色收尾——那会在图的下沿切出一条比页面更黑的带子；
  渐变也要在大图边缘之前淡完，图不存在「被硬切一刀」的边；
- **详情页顶部**：整块横版图铺满（没有横版图就用海报放大模糊），信息压在图的下半部，
  一列竖排：标题 → 原名 → 年份 / 类型 / 集数 → 标签 → 简介（最多 4 行，宽 860）→
  动作按钮，**不要**再叠一张竖版海报卡；上下各压一层渐变，保证白字压在亮图上也能读；
  Windows 与 macOS 用同一套排布；
- **续播要一目了然**：进详情时正在看的那一集自动高亮（集卡强调色描边、集号变色），
  选集行滚到它；主按钮写成「播放 第 N 集 + 续播时间」，快捷选集段也跟着那一段亮。
  高亮和自动滚动只做一次，之后用户自己滚到别处不能被补页 / 刷新拽回来。两端一致。
- **进度条别和高亮抢一条线**：集卡进度条距底边、左右各缩进 4px（圆角），
  高亮集的进度条用白色填充（其余用强调色）：贴底边时强调色描边和强调色进度
  会连成一条，看起来像「高亮把进度条吃掉了」。看完的集（进度 ≥99.5%）不画
  进度条——整条满格会让人以为没看完；阈值两端统一。
- **点卡片的默认动作**：一律进详情页，**不要**按条目类型直接起播；
  唯一例外是「继续观看」这类带播放进度的卡片，点进去续播。搜索、网格、
  收藏、库分组海报都走详情；
- **从详情返回要回到原处**：列表页的筛选（类别 / 排序 / 风格 / 页内搜索）、
  分页和滚动位置都保留，不能退回默认的「全部」或顶部；返回时只重拉已加载的
  页更新进度 / 收藏，不重置筛选。两端一致。
- **详情页动作按钮**：一行「图标 + 文字」的胶囊按钮，顺序固定：播放（主色
  `HeroPlayButton`）→ 重头看 → 加入收藏 / 已收藏 → 标记为已观看 / 标记为未观看
  → 音轨（`audios > 1` 才出现）→ 字幕（有字幕轨就出现）→ Trakt（包里有应用凭据
  `Trakt / DVTraktClientId` 时才出现，点开是评分 / 收藏 / 待看）。二级按钮走
  `HeroActionButton`（`GhostButton` 的深色半透明版），激活态图标变 `AccentColor`
  且文字跟着变（「已收藏」「标记为未观看」）。飞牛这类源的图标字形 16px 下认不出，
  所以**必须有文字**，不要只放圆形图标。文案要和 macOS 保持一致。
  字幕图标不用 `Segoe MDL2` 的字幕字形，用 `Viewbox` 画「方框 + 两条字幕条」。
- **续播点合并（电影 / 视频）**：同一部片在其它源或 Trakt 上进度更远时，按百分比
  取较长的那条换算成当前源的位置；差不足 1% 保留本地，≥99.5% 算看完、从头播。
  剧集不跨源合并（各源记录的集号不同）。
- **Trakt 只做「整部片 / 整部剧」**：评分（1–10）、收藏（collection）、待看
  （watchlist）都在详情页的 Trakt 菜单里，点开时先读一次当前状态；播放进度由
  播放页自动 scrobble，不在详情页手动标。匹配优先用源里的 TMDB / IMDb id
  （Emby / Jellyfin 的 `ProviderIds`），没有才按「片名 + 年份」：标题
  完全一致优先，中文片名对不上时按年份差 ≤1 认第一条；宁可没有也不挂错。
- **详情页链接区**：先「豆瓣」（按片名搜索），有 TMDB / IMDb id 时在后面追加
  「TMDB」「IMDb」两个胶囊按钮，没有就只显示豆瓣；两端一致。
- **「关于」页**：应用 / 共享核心版本、完整项目地址（点开系统浏览器）、更新状态
  （已是最新 / 发现新版本 / 网络失败）；标签和值用同一个 Grid 对齐，不要一行一个
  缩进。启动后在后台查一次更新，有新版只在侧栏左下角版本号下加一行「可更新 vX」，
  不弹窗、不挡启动；能从侧栏状态点看出的信息（已连接等）不重复放。
- **媒体信息卡**：视频一张，每条音轨 / 字幕各一张。音轨和字幕卡整张可点，
  点了就切到那条轨（单选），标题后的勾和顶部按钮文案同时更新；视频卡不可点。
- **字幕默认选择**：手动选过就听手动；没选过时优先中文字幕（简体 > 繁体 > 任意中文），
  再退回服务器默认轨，都没有就当关闭。语言字段可能是 `chi` / `cmn-Hans` / `中文`，
  标题常见 `Simplified Chinese`，几处都要认；按钮和菜单统一显示「简体中文 / 繁体中文 / 中文」，
  不要露出 `zh`、`Simplified Chinese` 这类原文。Windows 播放页在没有记忆时
  还会按 mpv 轨道的 `lang` / `title` 兜底打开中文字幕（续播、播放页切集的路径）。
  选项弹深色 `ContextMenu`，当前项左边打勾；选择结果写进 `Services/TrackPrefs`，
  播放器拿到 mpv `track-list` 后按 `aid` / `sid` 应用一次，播放页里再改会同步回去；
- **播放页**：视频由 mpv 自绘（Windows `--wid` 挂进 `MpvHost`；macOS 用进程内
  libmpv 画进同一窗口，控制浮层叠在上面，见 ADR-0011），壳只画浮层，
  顶部只有片名居中，**不放返回箭头**（看不懂，关闭用右上角的 ✕ 或
  Esc）；顶栏 48 高，渐变压在 100 内淡完，不做实底；右上依次是缓存速度
  （为 0 时不显示）、静音标记、最小化（`E921`）/ 最大化还原（`E922`/`E923`）/
  关闭（`E8BB`，悬停红底）。最大化是「铺满工作区」，和全屏不是一回事；
  右侧中部两个圆形按钮「截图」「选集」，选集从右侧弹出（380 宽、当前集高亮）；
  底部一行规格 chips（`HW` / 编码 / 动态范围 / 分辨率 / 帧率 / 比特率），
  动态范围那格显示**实际输出**（`DV P5/P7/P8` / `HDR10` / `HLG` / `SDR`，
  取自 mpv，拿不到时才退回服务端刮削的值）；
  下面控制条：上一集 / 播放暂停 / 下一集 / 当前时间 / 进度 / 时长 /
  静音 / 音量（`VolumeBar`）/ 音轨 / 字幕 / 倍速 / 全屏 / 更多（下一集、全屏、
  硬解码开关、媒体信息、打开日志目录）。没有上一集 / 下一集时给一句提示
  （「已经是第一集」/「这条没有选集」），不要静默失败；±10 秒只保留在
  键盘 ←/→ 上。进度条和音量条**点轨道就能跳 / 调**（不用非得抓住那个小圆点）：
  拖动过程只动 UI，松手才 seek，网络流不会被拖出满屏缓冲；整条 18px 都可命中，
  模板根节点要有 `Background="Transparent"`，否则只有中间 4px 的线能点。
  **进度条分三层上色**：已观看 = 主色（`AccentBrush` / `Theme.accent`）、已缓冲 =
  亮白（65%）、未观看 = 暗白（24%），一眼能看出「看到哪 / 下好多少 / 还剩多少」。
  已缓冲位置取 mpv 的 `demuxer-cache-time`（绝对时间戳）；自绘三层、上面盖一个
  只画滑块的 Slider，点击 / 拖动照旧。
  浮层 3 秒无操作淡出，鼠标一动就回来，光标同时跟着隐现；
  单集没有标题时顶栏用「剧名 + 集号」拼，不显示「（未命名）」；
  画面单击暂停、双击全屏、滚轮调音量，鼠标 3 秒不动连光标一起收起来；
  播完自动接下一集；**最后一集、或者电影这类没有选集的，播完直接关窗口**；
  「更多」里也有下一集 / 全屏；
  从「记录」续播也要带上那一季的选集（`Views/Playlists.cs`：先试记录的
  `ParentId`，飞牛的记录只给剧名，就按剧名搜回剧集 id 再取那一季），
  否则续播打开只剩一个孤零零的片子，没有选集和上一集 / 下一集；
  **在播放页里切集一律从头开始**（选集面板、上一集 / 下一集、播完自动接的下一集）：
  续播点是「上次看到哪」，已经看完的集会带着片尾位置回来，一加载就 EOF 又跳下一集；
  同理，**记录停在片尾的片**（已经看完）从详情页 / 媒体库打开时也从 0 开始，
  不会一打开就关窗——只有真的从片尾播过去才算「播完」；
- **画面比例**：「更多」里给五个选项——适应窗口（默认）/ 填充窗口（裁切）/ 拉伸铺满 /
  强制 16:9 / 强制 4:3，当前项打勾。实现是 mpv 的 `keepaspect` + `panscan` +
  `video-aspect-override`；比例是逐文件属性，换集后要重新套一次。选择写进本地配置，
  下次开播放器还用它。
  **适应窗口要连视频分辨率 / 方向一起适应**：窗口跟着视频的显示宽高比变形状
  （竖屏短剧就收成竖窗口，横屏电影保持 16:9），画面正好铺满客户区，左右 / 上下
  不留黑边；同一次播放里用户手动改过窗口就听用户的，换集或重开再按新视频适配。
  填充 / 拉伸 / 强制比例只改画面、不动窗口。窗口窄于约 700 像素时（竖屏短剧就会
  这样），底部控制条**只减不增，不做第二行**：只留上一集 / 播放 / 下一集 / 时间 /
  进度 / 时长 / 更多，静音、音量 ±10、音轨、字幕、倍速这些工具全部收进「更多」，
  一行放得下，画面也不会被多一行控件压掉。
- **定时关闭**：「更多」里 15 / 30 / 45 / 60 / 90 分钟 / 本集结束后，另有一项取消。
  设定后底部规格 chips 里显示剩余时间（`定时 12:34`），到点先提示再关播放窗，
  进度照常回写；「本集结束后」是在自然播完那一集时关窗，不接下一集。暂停状态也要计时。
- **片头片尾跳过**：手动标记、按剧记忆（同一部剧所有集通用），存本地
  `skip-markers.json`。播到片头结束点，在「更多」里点「把当前位置设为片头结束」；
  片尾同理。之后起播点落在片头之前就自动跳到片头结束（续播点已经在后面则不动）；
  进入片尾区间浮出「跳过片尾」按钮，点了直接接下一集，**不自动跳**。
  「更多」里可以分别清除，也可以一键清除本剧全部标记。电影没有剧名，按键 = 条目 id。
- **弹幕 / 字幕搜索**：弹幕开关在控制条上、紧跟「字幕」按钮（开着显示强调色），
  只有窄窗把工具收进「更多」时才出现在菜单里。开了以后按「剧名 + 集号」自动匹配，
  和正片字幕**同时显示**（不抢占用户选的字幕）；底部 chips 显示 `弹幕 120`。
  字幕搜索打开右侧 `字幕搜索` 面板（380 宽）：
  语言 + 发行名 + 下载数，点一条就下载并立刻选中；没配 API Key 时面板里直接
  写清缺什么，不弹系统对话框。
  Windows 端没有独立的搜索面板，「搜索字幕…」在「更多」里就地弹出结果菜单，
  见 [M2-WINDOWS.md](M2-WINDOWS.md)；macOS 的浮层细节见 [M2-MACOS.md](M2-MACOS.md) §4.5–4.7。
- **打开播放器要立刻有反应**：点卡片先把播放窗显示出来（`正在打开…` + 片名），
  再去解析播放地址、起 mpv；不要等取完地址才开窗。取续播的选集更慢（服务端
  `/item/list` 要好几秒，边播边取还会被拉流挤慢），所以续播先把记录本身播起来，
  选集在后台拼好再补进右侧面板；`PlayWindow.OpenAsync` 里有防重闸门，
  开窗期间 / 刚开完的连点直接忽略，不会弹出一串播放器。
- **播放页窗口**：默认开成 16:9 的窗口（最宽 1600、屏幕八成宽，放不下就缩到九成高），
  `F11` / `Enter` / 双击画面进全屏，`Esc` 先关面板、再退全屏、最后才关窗口；
  四边 8px 内按住改大小（鼠标贴边会变对应光标），顶栏那一行按住拖窗口。
  这两件事都用 15ms 定时器读光标 + 左键状态来做，不走系统的非客户区：
  浮层是分层窗口，`WM_NCHITTEST` 那套不可靠，而且窗口跟着鼠标跑时
  跨窗口的移动/抬起事件会丢。控制条打开时就是可见的，3 秒无操作才淡出；
- **视频与浮层分两个窗口**：WPF 的 `HwndHost` 是原生子窗口，会盖住同一窗口的
  WPF 内容（airspace），控制条画在旁边根本看不见。所以视频放在
  `Player/PlayerSurfaceWindow`（无边框黑窗，只有 `MpvHost`），控制条是
  `PlayWindow`（`AllowsTransparency` 的浮层），两者的 `Left/Top/Width/Height`
  由播放窗口同步，所有权是「视频 ← 浮层」：浮层认视频层当 Owner，所以永远在
  视频上面，不用抢 z 序。任务栏里**只留视频窗口**（缩略图有画面、
  `ShowInTaskbar=true`），浮层必须显式 `ShowInTaskbar="False"`——
  分层窗口的缩略图是空白，两个都进任务栏就会看到两条「正在播放」。
  从任务栏点回来时激活的是视频窗，浮层再把焦点拿回来。
  **播放窗不归主窗口所有**：媒体库和播放器是两个独立窗口，最小化媒体库时
  应该继续看，不能把播放窗一起收走。只有主窗口关闭（应用退出）时，播放窗才跟着关。
  **两层必须同进同出**：最小化播放窗时分层浮层不会跟着走，于是桌面上只剩一条
  控制条。播放窗每 1 秒（以及视频层的 `StateChanged`）自愈一次：视频层最小化 /
  不可见就 `Hide()` 浮层；视频层回来了就 `Show()` + 同步矩形 + `Activate()`。
  最小化按钮也走同一条路：先藏浮层再最小化视频层。
  浮层根节点的底色必须是 `#01000000` 这类 alpha=1 的色，**不能是 `Transparent`**：
  分层窗口 alpha=0 的像素会让鼠标穿透到下面那层，点画面就收不到事件了；
- **macOS 是单窗口**：libmpv 在进程内用 render API（gpu-next + OpenGL）画进自己的
  `NSOpenGLView`，控制浮层是同一个窗口里叠在上面的 SwiftUI 层（不是独立窗口），
  所以不需要跨窗口同步几何。全屏是「假全屏」——窗口铺满屏幕 + 隐藏菜单栏 / Dock，
  不进系统 fullscreen space。浮层那一套视觉规则和 Windows 完全一致；
- **海报网格**：一律用 `Controls/PosterGrid`，不要在页面里自己算列宽。
  它按可用宽度算列数（`floor(宽度 / (MinCardWidth + 16))`），卡片宽度铺满格子，
  窗口变宽不会在右侧留白；翻到下一列时卡片缩回去。默认是 2:3 竖版海报，
  `CardRatio`（宽 / 高）可以换成别的比例，`MinCardWidth` 改列宽下限——
  记录页「观看」就是 `CardRatio="1.7778"`（16:9 横卡）+ `MinCardWidth="220"`。
  卡片模板里绑 `CardWidth` / `CardHeight` / `CardSlot`（`RelativeSource
  AncestorType=controls:PosterGrid`），页面只提供 `ItemTemplate`，别各写一份
  尺寸计算；`ScrollViewer` 里要给网格套一层 `StackPanel`（或在模板里撑满），
  否则 `ActualWidth` 可能停在内容自己的期望宽度，算少一列；
- **图片**：海报按容器解码，不放大低分辨率图；Hero 优先横版图。

## 5. Android（手机 / TV）

色板与字号沿用 §1–§2，不新增色相。差异在尺寸与交互：

| 项 | 手机 | TV |
| --- | --- | --- |
| 基准 | 360dp 宽、16dp 边距 | 960×540 dp 基准、5% overscan 安全区 |
| 正文 | 14sp 起 | 16sp 起（10-foot） |
| 触控 / 焦点 | 最小 48dp 命中 | 焦点框 2dp 主色，永不隐藏 |
| 导航 | 顶部分段 + 手势 | 遥控器 DPAD，焦点可恢复，返回逐层退出 |
| 播放器 | 手势 seek / 亮度 / 音量、锁屏、PiP | 左右 seek、上下切轨、OK 暂停 |
| 其他 | 媒体通知、下载 | 保持常亮，无通知 / 下载 |

组件库不同（`material3` 与 `androidx.tv:tv-material`），**共享设计令牌与 UiState，
不共享屏幕布局**（[ADR-0013](adr/0013-android-two-shells.md)）。播放页底部那行
规格 chips 在两端都要显示**实际输出**（内核 / 动态范围 / 分辨率 / 帧率），
降级时写清原因（例如「DV P7 → 本机只播 BL」）。
