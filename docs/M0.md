# M0 技术验证

> 状态：进行中。开始于 2026-11-19。

## 1. 目标

M0 只回答三个问题，不做产品功能：

1. **FEL 真的被重建了吗？** 不是只播 BL，也不是转 P8.1。
2. **Windows 的 `wid` 子窗口路径能拿到 FEL 吗？**
3. **macOS 的 render API 能正确输出吗？** HDR10 可用，或明确退 SDR。

### 2026-11-19 NAS 片源核查（10.0.0.100）

目标文件：

```
/vol1/1000/影视/I.Will.Find.You.2026.S01.2160p.NF.WEB-DL.DDP5.1.Atmos.DV.H.265-DepWeb/
  I.Will.Find.You.2026.S01E01.2160p.NF.WEB-DL.DDP5.1.Atmos.DV.H.265-DepWeb.mkv
```

远端 `ffprobe`（NAS 自带 `/usr/bin/ffprobe`）读出：

| 字段 | 值 |
| --- | --- |
| 视频轨数 | 1 |
| codec / profile | hevc / Main 10 |
| 分辨率 | 3840×2160 |
| pix_fmt | yuv420p10le (pc) |
| dv_profile | **5** |
| el_present_flag | **0** |
| rpu_present_flag | 1 |
| bl_present_flag | 1 |
| dv_bl_signal_compatibility_id | 0 |

**结论：不满足 A1/A2 的条件。** 这是 Dolby Vision Profile 5（单层、IPTPQc2），
没有增强层，`el_present_flag=0`。NETFLIX WEB-DL 的 DV 基本都是 P5，这条经验在这里被证实。

已用 `scripts/nas-fetch-sample.sh` 从第 30 秒无损切 20 秒拉到 `samples/p5.mkv`
（39 MB，4K24，含 EAC3 Atmos 与 7 条字幕轨），本地 `prefix/bin/ffprobe` 复核结果一致。

用途调整：`samples/p5.mkv` 转作 **P5 回归样本**（验证 P5 颜色正确性、徽标应显示 `DV P5`），
不再作为 A1/A2 的输入。

A1/A2 仍然缺 **真正的 P7 双层片源**。可行的来源：UHD 蓝光 remux 的
`Profile 7`（BL+EL+RPU），或公开测试片（dovi_tool 仓库与 Dolby 的样片）。
